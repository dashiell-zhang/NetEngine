# ID 生成器

宿主注册一个 `IdentifierGenerator.IdService`，由业务实体、日志、数据库事件和队列复用。模板使用共享 Redis 自动分配雪花节点，保持现有 ID 布局，不按业务数据库分别创建发号器

## 自动节点注册

```csharp
services.AddIdentifierGenerator(options =>
{
    options.RedisConfiguration = sharedIdRedisConnection;
});
```

参与同一 ID 唯一性范围的宿主使用相同 Redis 目标、库编号、节点前缀。不同宿主的业务缓存和锁可以使用不同 Redis 库编号；不能让 ID 协调随业务锁一起隔离。模板宿主通过 `idRedisConnection` 选择共享目标，未配置时由宿主选择业务 Redis

`InstanceName` 默认 `NetEngine.Identifier`。重复注册 IdService 会报错。组件只引用公共实体或只查询日志时，不需要注册 ID 服务；启用日志写入、队列入队或数据库事件时需要

## 租约和故障

首次解析自动 IdService 时连接 Redis，通过带所有者令牌和有效期的原子条件写入占用节点，竞争失败则继续尝试其他候选节点，再确认所有者和剩余有效期。Redis 访问失败、结果未确认或节点耗尽会使初始化失败，不会按空闲节点继续发号

节点总容量为 32 × 32。`LeaseDuration` 默认两天，可配置范围为 3 秒至 30 天；生产各实例保持一致。退出实例保留占用直到自然到期，因此容量按未过期的占用数计算，包含近期退出的进程

占用成功后立即开始独立续期，不等待宿主后台服务启动，因此 EventBus 初始化等待不会阻断续期。续期原子校验所有者与有效期，不覆盖新持有者，也不重新创建已经到期的键

GetId 检查本地保守有效期。短暂续期故障不会立即否定尚有效的租约，但不会延长有效期；到达有效期后停止发号。在 Redis 键仍有效且确认同一所有者续期成功时可恢复。键已到期或所有权已丢失时，本实例停止发号，需要修复依赖并重启实例重新分配节点

节点占用数据不能作为可随意清理、淘汰的缓存。共享 Redis 应保留这些键；若占用数据丢失，先停止该唯一性范围内的发号实例，再重新建立分配。仅配置相同连接不能替代这一运维约束

ID 诊断写到独立标准错误，不通过数据库日志递归记录。首次日志落盘需要 ID；租约失效时新日志只能在有界缓冲内等待，容量或停机期限耗尽可能丢弃，已有稳定 ID 的积压文件仍可入库

## 固定编号

明确管理唯一节点编号的场景可以同时配置 `DataCenterId` 和 `MachineId`，各为 0 至 31，此模式不使用 Redis。不要给多个副本复制相同编号，也不要将固定节点直接混入自动分配范围；模板的常规多实例部署使用自动节点
